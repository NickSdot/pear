[2006-12-01 15:50 UTC] michelo at rigadev dot com

Description:
------------
The english manual page on Coding Standards file formats, http://pear.php.net/manual/en/standards.file.php, states "There should be one line feed after the closing PHP tag (?>). This means that when the cursor is at the very end of the file, it should be one line below the closing PHP tag." I believe this is incorrect as it can lead to problems if a class file is included before the html headers are sent.

This should be rewritten to state that no characters should appear before the opening <?php or after the closing ?> including line feeds and other control characters.

Thanks,

Test script:
---------------
---- source1.php ----
<?php
?>

---- source1.php end ----
---- source2.php -----
<?php
require_once('source1.php')
header("HTTP:/1.0 404 Not Found");
?>

Expected result:
----------------
Warning: Cannot modify header information - headers already sent by (output started at www.example.com/source1.php:4) in www.example.com/source2.php on line 3

[2006-12-08 18:34 UTC] michelo at rigadev dot com

Most of the files that I have examined are fine but this seems to be at odds with coding standards which seem to require a single line feed after the closing ?>. Most of the PEAR .php files do not have a line feed after the closing ?>.
